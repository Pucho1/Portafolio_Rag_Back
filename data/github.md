# Clasificación de evidencia

Para interpretar correctamente la información de GitHub se utilizan las siguientes categorías:

### Proyecto personal relevante

Proyecto desarrollado por Miguel que aporta evidencia significativa sobre una capacidad técnica.

Ejemplos:

* Portafolio_Rag_Back.
* MCPserver.
* Task-Manager.
* Tienda-Outlet.

### Proyecto de IA

Proyecto relacionado directamente con Inteligencia Artificial, LLM, agentes, RAG o MCP.

Ejemplos:

* Portafolio_Rag_Back.
* LangChainAgent.
* MCPserver.
* weather_MCP_Server.

### Proyecto de aprendizaje o experimentación

Repositorio utilizado para aprender, probar o explorar una tecnología.

Estos proyectos no deben utilizarse por sí solos para afirmar experiencia profesional.

### Experiencia profesional

La experiencia profesional debe determinarse principalmente a partir de `experience.md` y del CV. Un repositorio público no debe considerarse automáticamente parte de la experiencia profesional.

# Regla de interpretación

La información obtenida de GitHub representa **evidencia técnica pública**, no una descripción completa de la trayectoria profesional.

Cuando exista información diferente entre GitHub y el CV:

1. El CV debe utilizarse como fuente principal para la trayectoria profesional declarada.
2. GitHub debe utilizarse como evidencia pública de proyectos y código.
3. Los proyectos privados pueden incorporarse posteriormente si Miguel proporciona información sobre ellos.
4. No deben inferirse responsabilidades profesionales únicamente a partir de un repositorio.
5. No debe atribuirse a Miguel código de terceros, forks o proyectos que no haya desarrollado.

La información de este documento debe mantenerse actualizada a medida que aparezcan nuevos proyectos públicos relevantes.
